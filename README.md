# Вуаль 1.7.0

«Вуаль» — приложение с учётными записями, защищёнными исходными документами,
конвертацией и просмотром таблиц. В версии 1.7.0 добавлен центральный сервер
учётных записей для локальной сети.

- Сервер хранит основную `users.db` и проверяет пароли и права администратора.
- Изменения аккаунтов сохраняются в транзакции и автоматически передаются
  работающим клиентам при следующей проверке, примерно каждые 2 секунды.
- Окно **«Подключения пользователей…»** показывает всех остальных пользователей:
  зелёный — работает, серый — нет подключения, красный — деактивирован.
- Там же администратор может разблокировать сетевую блокировку или восстановить
  деактивированный аккаунт. Пользователь входит заново со своим действующим паролем.
- Прежние данные, JSON-таблицы и зашифрованные резервные файлы поддерживаются.

## Запуск на Windows

Распакуйте весь архив и запустите **«Запустить.bat»**. При первом запуске скрипт
собирает **«Вуаль.exe»** и **«Вуаль-сервер.exe»**. Для сборки нужны Python 3.10+
и интернет. Готовые EXE в архив не включены; Windows-сборка в Linux не проверялась.

Для отдельной работы на одном компьютере оставьте сетевой режим выключенным.
В пустой базе первое окно позволяет задать пароль администратора `admin_admin`.

## Настройка локальной сети

Выберите один компьютер сервером. В командах ниже `192.168.1.10` — пример:
замените его реальным IPv4-адресом сервера, который можно узнать командой `ipconfig`.

**Первый запуск сервера с новой пустой базой:**

```bat
"Запустить сервер.bat" --init-tls --server-name 192.168.1.10 --host 0.0.0.0 --bootstrap-admin
```

Пароль администратора задаётся в консоли. Если в каталоге данных уже есть
учётные записи, используйте эту команду **без** `--bootstrap-admin`.
Первоначальная настройка не заменяет существующие аккаунты или пароли.

**Следующие запуски, с уже созданным сертификатом:**

```bat
"Запустить сервер.bat" --host 0.0.0.0
```

Сервер выводит путь к открытому сертификату `server.crt` и его SHA-256.
Скопируйте **только открытый сертификат** на клиентские компьютеры доверенным
способом. Ключ `server.key` хранится на сервере. Имя/IP в адресе подключения
должно совпадать с именем/IP, указанным при создании сертификата.

В брандмауэре сервера разрешите входящие подключения TCP к порту **8765** для
нужной локальной сети. Сервер должен работать постоянно; окно администратора
не требуется для обработки клиентских сигналов.

На каждом клиенте:

1. Откройте «Вуаль» и нажмите **«Подключение к серверу…»**.
2. Включите использование сервера, задайте `https://192.168.1.10:8765`, выберите
   скопированный `server.crt` и укажите имя компьютера.
3. Сохраните настройки и войдите с серверной учётной записью.

Для серверного администратора можно использовать клиент на том же компьютере
с адресом `https://127.0.0.1:8765` и тем же сертификатом. Управление аккаунтами
доступно во вкладке **«Учётные записи»**; изменения выполняются на сервере.

## Подключения и восстановление

Статус сети подтверждает авторизованное приложение, отправляющее HTTPS-сигнал.
Проверка сертификата обязательна; пароль и токен не сохраняются в сетевых настройках.

| Цвет | Статус | Условие |
| --- | --- | --- |
| Зелёный | Работает | Активный аккаунт, действующий сеанс, сигнал за последние 10 секунд |
| Серый | Нет подключения | Нет свежего сигнала, сеанс завершён либо действует сетевая блокировка |
| Красный | Деактивирован | Администратор деактивировал аккаунт, независимо от прежних сигналов |

Табло обновляется примерно каждые 2 секунды и показывает IP-адрес, имя компьютера,
последний сигнал и действия. Текущий администратор исключён из списка.
Выделите красного пользователя и нажмите **«Разблокировать выбранного пользователя»**,
затем подтвердите активацию. Сетевая блокировка снимается той же кнопкой.
Восстановление сохраняет пароль и историю, очищает ошибки входа и завершает
прежние сеансы. Оно не восстанавливает старый сетевой токен.

Без сигнала 5 минут сервер завершает сетевой сеанс. Восстановление соединения
требует нового входа. При недоступном сервере клиент завершает локальный сеанс
и очищает открытые данные; вход по локальной копии в сетевом режиме не предусмотрен.

## Данные и обновление users.db

Основная база аккаунтов лежит на сервере в каталоге данных. При создании аккаунта,
изменении его прав или пароля, деактивации, восстановлении и блокировке увеличивается
номер изменений. Клиенты применяют новые данные в одной транзакции SQLite.
Открытый файл базы не заменяется копией целиком: связи с владельцами документов,
таблиц и журналом сохраняются. Новые изменения не требуют ручного копирования `users.db`.

Клиентская копия содержит метаданные аккаунтов; хеши паролей с сервера не передаются.
Пароли проверяются на сервере. Для разных адресов серверов используются отдельные
каталоги клиентов, чтобы не смешивать учётные записи и локальные документы.
При замене серверной базы или откате её версии клиент останавливает синхронизацию
с объяснением: администратору нужно согласовать восстановление и новый клиентский кэш.

Таблицы и исходные документы остаются в локальной библиотеке соответствующего
рабочего места. Эта версия синхронизирует учётные записи и присутствие в сети;
перенос библиотеки документов на сервер не реализован.
Подробности трёх баз, форматов и резервного копирования — в [DATABASES.md](DATABASES.md).

Аварийный сброс всех паролей и подготовка резервных файлов выполняются через
локальное окно администратора на сервере с его основной `users.db`.
На сетевых клиентах эти кнопки отключены, чтобы не изменять только клиентскую копию.

## Запуск из Python

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python src/main.py
# Сервер на Linux/macOS, первый запуск:
.venv/bin/python src/server_main.py --init-tls --server-name 192.168.1.10 --host 0.0.0.0 --bootstrap-admin
```

На Windows используйте `.venv\Scripts\python` вместо `.venv/bin/python`.
После установки пакета доступны команды `vual`, `vual-server` и `vual-bootstrap`.

Результат проверок этой поставки записан в `TEST_RESULTS.txt`. Проверки сетевого
сценария используют настоящий HTTPS-сервер и разные клиентские базы на loopback;
работу в вашей физической локальной сети нужно проверить после настройки IP и брандмауэра.
