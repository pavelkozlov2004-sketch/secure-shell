# Три базы данных — версия 1.6.0

Приложение создаёт три отдельных файла SQLite в каталоге данных. По умолчанию
это `~/.secure-shell`; другой каталог можно указать переменной
`SECURE_SHELL_DATA_DIR` перед запуском.

| База | Что хранится | Доступ через приложение |
| --- | --- | --- |
| `users.db` | Учётные записи, хеши паролей, роли, направления и уровни доступа, сеансы и аудит | Пользователь меняет собственный пароль; администратор управляет аккаунтами |
| `tables.db` | Содержимое сохранённых таблиц, владелец, метки доступа и ссылка на исходник | Администратор управляет таблицами; пользователи просматривают таблицы своего направления в пределах уровня доступа |
| `documents.db` | Полный текст исходных документов, название, имя импортированного файла, владелец и версия | Только действующий аккаунт с правами администратора |

## Запуск

1. Распакуйте весь архив. На Windows запустите `Запустить.bat`; при первом запуске
   он собирает EXE, для чего нужны Python 3.10+ и интернет. Готового Windows EXE
   в архиве нет.
2. При первом открытии пустой базы задайте пароль администратора в окне настройки.
   Войдите как `admin_admin` с выбранным паролем.
3. Во вкладке **«Учётные записи»** создайте пользователей, назначьте им направление,
   уровень доступа и при необходимости права администратора. Там же можно изменить
   права, сбросить пароль или деактивировать аккаунт.
4. Откройте **«Библиотека»**. Администратор может создать или импортировать исходный
   документ, изменить его текст и сохранить. Конвертация создаёт отдельную таблицу,
   которая хранится в базе и открывается во вкладке **«Таблицы»**.
   Чтобы выдать пользователям доступ к результату, выделите таблицу в библиотеке
   и нажмите **«Права таблицы…»**: выберите направление и уровень доступа. Сразу
   после создания таблица наследует направление и уровень её создателя.
5. Обычный пользователь видит доступные ему сохранённые таблицы. Исходные документы
   ему недоступны, включая просмотр списка и любые обращения к сервису хранения.

Для запуска из исходников:

```sh
python -m venv .venv
# Linux / macOS:
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python src/main.py
# Windows:
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python src\main.py
```

## Формат исходных данных

Поддерживается текст UTF-8 до 2 МиБ. Можно импортировать `.txt`, `.csv`, `.tsv`
или `.json`. Расширение не меняет проверки содержимого.

Конвертация принимает:

- JSON с форматом `secure-shell-table-v1`, как в `examples/report-template.json`;
- текст с разделителем: табуляция, точка с запятой или запятая. Каждая запись
  содержит 13 ячеек в порядке столбцов существующей ведомости. Необязательная
  первая строка может содержать названия этих столбцов.

Пример текста: `examples/source-document.tsv`. Порядок столбцов:
`№`, `Код`, `Описание объекта`, `Местоположение`, `Участок`, `А`, `Б`, `В`, `Г`,
`Количество`, `Время`, `Ответственный`, `Примечание`.

Свободный текст без такой структуры требует предварительного редактирования.
RTF и DOCX необходимо предварительно преобразовать в поддерживаемый текст.
Приложение сообщает о неверном числе ячеек, некорректном JSON и превышении лимитов,
не сохраняя частичный результат.

## Связи и изменения

У документов и таблиц есть `owner_id`, связанный с аккаунтом в `users.db`.
Таблица может хранить `source_document_id` и `source_revision`, которые указывают
на документ в `documents.db` и номер его версии при конвертации. Импорт готовой
таблицы допускается без исходного документа.

Редактирование документа увеличивает его версию. Ранее созданная таблица
остаётся сохранённым результатом прежней конвертации; повторная конвертация
создаёт новый результат. Параллельное изменение документа блокирует сохранение
устаревшей версии редактора. Документ, на который ссылаются таблицы, нельзя удалить
до удаления связанных результатов. Деактивация пользователя сохраняет его
документы, таблицы и историю.

SQLite не поддерживает внешние ключи между разными файлами баз. Приложение
подключает все три базы к одному соединению и проверяет связи триггерами и при
запуске. Изменения связанных записей выполняются в общей транзакции.
Не изменяйте эти базы сторонними SQL-инструментами без проверки связей.

Права проверяются при каждой операции хранения по текущему сеансу и текущей роли.
Отзыв сеанса, блокировка или снятие административных прав запрещают последующие
операции; открытые данные очищаются при ближайшем обновлении окна.
Пароли хранятся как PBKDF2-хеши с индивидуальной солью, а не открытым текстом.

Разграничение доступа действует внутри приложения. SQLite-файлы содержат данные
в незашифрованном виде: доступ к каталогу данных следует ограничить средствами
операционной системы. Эта локальная версия не является сервером для нескольких
компьютеров с разными правами на прямой доступ к файлам базы.

## Обновление и резервное копирование

Перед обновлением закройте все экземпляры приложения и сохраните копию каталога
данных. При первом запуске новой версии прежняя `secure_shell.db` автоматически
копируется в `users.db`, если новой базы ещё нет. Учётные записи, пароли, сеансы,
метаданные файлов и аудит сохраняются; исходный файл остаётся на месте.
После перехода рабочая база аккаунтов — `users.db`. Старые версии приложения
следует закрыть: они продолжат работать с прежним файлом независимо.

Для резервного копирования закройте все экземпляры и копируйте **вместе**
`users.db`, `tables.db` и `documents.db`. Восстанавливайте комплект целиком в один
каталог. Разные локальные копии не синхронизируются.

Проверка из каталога проекта:

```sh
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -q
```

Фактический результат проверки поставки указан в `TEST_RESULTS.txt`.
