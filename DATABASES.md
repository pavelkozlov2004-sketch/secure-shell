# Базы данных Вуали

| Файл | Содержимое | Доступ в приложении |
| --- | --- | --- |
| `users.db` | Учётные записи, права, сеансы, аудит и версии обновлений | Администратор управляет аккаунтами; пользователь меняет собственный пароль |
| `tables.db` | Готовые таблицы, владелец, метки доступа, ссылка на исходник и его версию | Администратор управляет таблицами; пользователи просматривают разрешённые результаты |
| `documents.db` | Полные исходные тексты, имя файла, владелец и версия | Только действующий администратор |

По умолчанию новые данные находятся в `~/.vual` (на Windows:
`%USERPROFILE%\.vual`). Для другого каталога задайте `VUAL_DATA_DIR`.
Приложение автоматически использует прежний каталог с рабочей базой, если новый
ещё не содержит аккаунтов; существующие пользователи и пароли сохраняются.
Для сетевого клиента копия `users.db` и его библиотека располагаются в
`clients/<идентификатор-адреса-сервера>/` внутри каталога данных.

## Сетевые учётные записи

Сервер хранит основную `users.db`. Все сетевые операции с аккаунтами проверяют
текущий сеанс и права на сервере. Изменения фиксируются сразу; работающие клиенты
получают их при следующем сигнале, примерно каждые 2 секунды. Пароли остаются
в виде PBKDF2-хешей с индивидуальной солью на сервере, а клиент получает метаданные
своей рабочей среды без хешей и без резервных паролей.

Сетевая копия `users.db` не позволяет выполнить автономный вход. Обновление
атомарно сохраняет связанные документы, таблицы и журнал, а деактивация или
блокировка завершают прежние сеансы. Настройки подключения содержат адрес,
открытый сертификат и имя компьютера; пароли и токены в них не записываются.

## Таблицы и документы

Во вкладке **«Библиотека»** администратор создаёт или импортирует исходник UTF-8
до 2 МиБ, редактирует его, сохраняет и конвертирует. JSON с форматом `vual-table-v1`
принимается непосредственно, как в `examples/report-template.json` и трёх маленьких
примерах. Поддерживаются также CSV/TSV и текст с разделителем «точка с запятой».
В каждой строке 13 строковых ячеек в порядке:

`№`, `Код`, `Описание объекта`, `Местоположение`, `Участок`, `А`, `Б`, `В`, `Г`,
`Количество`, `Время`, `Ответственный`, `Примечание`.

Готовую таблицу можно загрузить кнопкой **«Импорт таблицы JSON…»**.
Для выдачи доступа выделите результат и нажмите **«Права таблицы…»**, выберите
направление и уровень. Исходник остаётся доступным только администраторам.
Свободный текст без структуры нужно подготовить перед конвертацией;
RTF/DOCX необходимо предварительно преобразовать в поддерживаемый формат.

У таблицы сохраняется `source_document_id` и версия исходника при конвертации.
Изменение исходника увеличивает его версию, а прежняя таблица остаётся сохранённым
результатом. Повторная конвертация создаёт новую таблицу. Редактор отклоняет
сохранение устаревшей версии; удалить исходник можно после удаления связанных таблиц.
Деактивация пользователя сохраняет его объекты и историю.

SQLite не поддерживает внешние ключи между файлами, поэтому приложение подключает
три базы к одному соединению, проверяет связи триггерами и выполняет связанные
изменения в общей транзакции. Права операционной системы должны ограничивать
прямой доступ к SQLite-файлам: разграничение доступа приложения не шифрует их содержимое.

## Обновление и резервная копия

Перед обновлением закройте приложения и сервер, сохраните копию каталога данных,
затем распакуйте новую поставку. Прежняя база учётных записей переносится автоматически
при отсутствии `users.db`; прежние форматы JSON и резервных файлов поддерживаются.
Старые версии следует закрыть на всех рабочих местах.

Для локальной библиотеки копируйте **вместе** `users.db`, `tables.db` и `documents.db`
при закрытом приложении. На сервере сохраняйте весь каталог данных, включая
сертификат и ключ, при остановленном сервере. После восстановления серверной базы
из старой копии клиент может остановиться из-за уменьшения версии: не заменяйте
его локальную базу наугад, сначала сохраните библиотеки и согласуйте их владельцев.

Полная настройка сети описана в [README.md](README.md).
